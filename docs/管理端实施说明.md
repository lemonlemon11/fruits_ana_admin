## 4. 启动

### 4.1 安装后端依赖

可使用现有 `fruits_ana/.venv`，或在管理端创建独立虚拟环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
```

### 4.2 启动后端

```bash
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001
```

### 4.3 初始化超级管理员

```bash
.venv/bin/python -m app.bootstrap --username test
```

> 当前环境已将 `test` 初始化为管理端控制台管理员，并绑定到 `fruit_admin` 业务角色。

### 4.4 启动前端

```bash
npm --prefix frontend install
npm --prefix frontend run dev -- --host 0.0.0.0 --port 54000
```

访问：`http://127.0.0.1:54000`

### 4.5 已有库菜单迁移

`seed.py` 只补缺、不修改既有记录，因此升级已有数据库需要执行一次迁移脚本：

```bash
cd backend
.venv/bin/python scripts/merge_import_entry_menu.py            # 演练，只打印待迁移项
.venv/bin/python scripts/merge_import_entry_menu.py --apply    # 写库
```

脚本幂等，可重复执行，动作包括：合并「手工录单」菜单的角色授权到「数据导入」、
删除残留菜单、重命名为「录单 / 导入」，并把 `entry:*` 权限点的 `module`
由 `entry` 改为 `import`（授权树按 `module` 归组）。
权限编码 `entry:*` 保持不变，`fruits_ana` 的 `/entry` 路由仍按它鉴权。

### 4.6 历史角色授权污染修复

角色授权页已区分业务权限与管理端权限：`GET /api/admin/permissions?scope=business`
只返回业务权限，角色保存与列表计数也只统计业务权限，`admin:*` 不下发到业务角色。

若旧数据已把 `admin:*` 或多余菜单写入系统角色，执行：

```bash
cd backend
.venv/bin/python scripts/repair_seeded_role_grants.py            # 演练
.venv/bin/python scripts/repair_seeded_role_grants.py --apply    # 写库
```

脚本幂等，会按 `FRUIT_ROLES` / `FRUIT_MENUS` 精确恢复 `fruit_admin`、
`operator`、`viewer`、`data_entry`、`registered_user` 的菜单与业务权限授权。

## 5. 默认角色

| 角色编码 | 名称 | 说明 |
| --- | --- | --- |
| `registered_user` | 新注册用户 | 新用户注册后的默认角色，不开放任何菜单和权限 |
| `fruit_admin` | 水果系统管理员 | 拥有 `fruits_ana` 全部业务菜单与权限 |
| `operator` | 运营人员 | 查看分析、处理导入并导出业务数据 |
| `viewer` | 只读分析员 | 只读查看分析与结算页面 |
| `data_entry` | 录单员 | 负责 `fruits_ana` 数据导入与录入 |
