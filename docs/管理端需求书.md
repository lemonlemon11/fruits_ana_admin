## 1. 背景与目标

### 1.1 背景

现有 `fruits_ana` 是面向果农的水果市场销售分析系统，技术栈为 Vue 3 SPA + FastAPI + MySQL。
目前系统只有基础的注册、登录、服务端会话能力，`user` 表仅包含 `display_name`、密码哈希、
状态和时间字段，没有角色、菜单、权限、审计等管理能力。

随着使用人员增加，需要一套独立的管理员端，用于：

- 管理登录用户；
- 分配角色、菜单和权限；
- 查看和管理业务数据；
- 追溯关键操作，降低误操作和安全风险。

### 1.2 目标

建设一个可独立访问、可扩展、可审计的管理员端，在不破坏现有果农端功能的前提下：

1. 实现用户、角色、菜单、权限的统一管理；
2. 实现后端强制鉴权，不能只依赖前端隐藏按钮；
3. 支持按角色动态生成果农端菜单；
4. 对关键操作留痕，支持查询和导出；
5. 为后续数据范围、多角色运营和业务数据治理预留扩展点。

## 2. 会议讨论摘要

以下内容为需求讨论中已形成的主要结论，用于约束后续设计与实现。

| 议题 | 讨论结论 | 优先级 |
| --- | --- | --- |
| 管理端与果农端关系 | 管理端独立前端项目，复用并扩展现有 FastAPI 后端，共享 MySQL 与 `user` 表 | P0 |
| 部署形态 | 管理端作为独立 SPA，由 Nginx 挂载到 `/admin`；Cookie 保持同域，复用现有登录体系 | P0 |
| 权限模型 | 采用 RBAC：用户 → 角色 → 菜单/操作权限；不直接给用户绑定散权限 | P0 |
| 权限粒度 | 至少支持菜单级、按钮/操作级、API 级权限点；数据范围权限首期只做“全部数据” | P0 |
| 角色策略 | 支持自定义角色，并内置超级管理员、运营管理员、数据录入员、只读审计员 | P0 |
| 菜单策略 | 菜单存数据库，管理 `fruits_ana` 业务菜单与权限；管理端自身导航固定 | P0 |
| 用户来源 | 管理员可创建用户；保留现有果农端注册，但可配置是否开放公开注册 | P0 |
| 审计范围 | 首期记录登录日志、用户/角色/菜单/权限变更日志；业务数据操作日志列入 P1 | P0 |
| 超级管理员保护 | 不能删除、禁用或移除最后一个超级管理员；超级管理员不能自锁 | P0 |
| 数据范围 | 现有业务数据没有归属人，首期所有管理员默认可见全部结算单，数据范围能力后置 | P1 |
| 密码策略 | 沿用 Argon2 哈希；管理端创建/重置密码时要求初始密码修改，密码策略可配置 | P1 |
| 多因素认证 | 首期不引入 MFA，后续可作为安全增强项 | P2 |
| 对外服务 | 首期只做管理端 Web，不承诺开放 API 给第三方 | Out of Scope |

## 4. 用户角色与场景

| 角色 | 主要场景 | 默认权限 |
| --- | --- | --- |
| 超级管理员 | 初始化系统、分配角色、维护菜单和权限 | 全部功能 |
| 运营管理员 | 管理用户、查看业务数据、查看审计日志 | 用户管理、业务数据查看、日志查看 |

## 5. 总体设计建议

### 5.1 系统形态

推荐采用：

```text
浏览器
  ├── /          → 果农端 Vue SPA（现有 fruits_ana）
  └── /admin     → 管理端 Vue SPA（fruits_ana_admin）
              ↓
        Nginx /api → 现有 FastAPI 后端
              ↓
          共享 MySQL
```

优点：

- 复用现有认证、用户表和会话机制；
- 管理端与果农端同域，Cookie 策略简单；
- 管理能力和业务能力集中在一个后端，权限拦截可覆盖所有 API。

### 5.2 后端扩展原则

- 新增 `/api/admin/*` 管理接口，避免污染现有 `/api/*` 业务接口；
- 新增权限依赖，例如 `require_permission("user:read")`；
- 权限校验放在服务端 API，前端菜单和按钮只是体验优化；
- 权限变更后及时失效相关缓存或重新加载用户权限。

### 5.3 数据模型扩展方向

在现有 `user`、`user_session` 基础上新增或扩展：

| 对象 | 说明 |
| --- | --- |
| `role` | 角色：名称、编码、状态、说明 |
| `permission` | 权限点：编码、名称、类型、所属模块 |
| `menu` | 菜单/按钮：父级、路由、名称、图标、排序、类型、权限编码 |
| `user_role` | 用户与角色关系 |
| `role_menu` | 角色与菜单关系 |
| `role_permission` | 角色与权限点关系 |
| `login_log` | 登录成功/失败、IP、UA、时间 |
| `operation_log` | 操作者、模块、动作、目标对象、变更前后、结果、IP |

兼容要求：

- 不能删除现有 `user_session`；
- 不能破坏现有 `user.display_name` 登录语义；
- 数据库迁移需提供幂等脚本，符合 `fruits_ana` 仓库现有迁移约定。

## 6. 功能需求

## 6.1 登录与会话

**FR-AUTH-001 管理员登录**

- 管理端复用现有 `POST /api/auth/login`；
- 登录成功后可访问 `/admin`；
- 未登录访问管理端时跳转到管理端登录页；
- 退出后同时失效当前服务端会话。

**FR-AUTH-002 权限拦截**

- 后端对 `/api/admin/*` 接口默认要求管理员权限；
- 果农端根据用户权限动态渲染菜单和按钮；
- 对无权限 API 返回 `403`，对未登录 API 返回 `401`。

**FR-AUTH-003 账号状态**

- 禁用账号不能登录；
- 已登录但被禁用的账号，后续请求应被拒绝；
- 管理员可强制下线指定用户的所有会话。

## 6.2 管理端工作台

**FR-DASH-001 系统概览**

- 展示用户总数、启用用户数、角色数、菜单数、权限点数；
- 展示最近导入批次数量、数据问题数量、近 7 日登录次数；
- 提供用户管理、角色管理、审计日志等常用入口。

## 6.3 用户管理

**FR-USER-001 用户列表**

- 支持分页、按用户名/状态/角色筛选；
- 展示用户名、角色、状态、最后登录时间、创建时间；
- 支持批量启用、禁用和删除确认。

**FR-USER-002 新建用户**

- 必填用户名和初始密码；
- 可同时分配一个或多个角色；
- 用户名沿用现有规范化唯一规则；
- 密码使用 Argon2 哈希，不在日志和接口响应中回显。

**FR-USER-003 编辑用户**

- 可修改显示名、状态、备注和角色；
- 不允许修改密码哈希本身；
- 修改关键信息需写入操作日志。

**FR-USER-004 重置密码**

- 管理员可生成临时密码或设置新密码；
- 用户下次登录时提示或要求修改密码，可作为后续配置项；
- 重置后强制失效该用户所有会话。

**FR-USER-005 禁用与强制下线**

- 禁用后立即阻止后续请求；
- 可撤销用户全部有效会话；
- 不能禁用当前超级管理员自己或最后一个超级管理员。

## 6.4 角色管理

**FR-ROLE-001 角色列表**

- 展示角色名称、编码、状态、用户数、权限概览；
- 支持分页、搜索和状态筛选。

**FR-ROLE-002 新建与编辑角色**

- 角色编码唯一，预置角色编码不可随意删除；
- 支持启用/停用；
- 保存时记录操作日志。

**FR-ROLE-003 删除角色**

- 存在用户绑定时禁止直接删除，或要求先解除绑定；
- 预置超级管理员角色不可删除；
- 删除需二次确认并记录日志。

**FR-ROLE-004 角色授权**

- 支持以树形结构勾选菜单；
- 支持勾选按钮/操作权限；
- 保存后立即生效，或明确刷新间隔。

## 6.5 菜单管理

**FR-MENU-001 菜单树**

- 支持目录、菜单、按钮三种类型；
- 展示名称、路由、图标、排序、状态、权限标识；
- 支持展开、收起和拖拽排序。

**FR-MENU-002 新建与编辑菜单**

- 目录：父级、名称、图标、排序、状态；
- 菜单：父级、名称、路由路径、组件路径、图标、排序、状态、权限标识；
- 按钮：父级菜单、名称、权限标识、排序、状态；
- 路由和权限标识在同一父级下不能重复。

**FR-MENU-003 删除菜单**

- 有子菜单或被角色引用时阻止删除或给出明确处理方式；
- 删除需二次确认。

**FR-MENU-004 菜单启用/停用**

- 停用后所有角色的对应菜单隐藏；
- 已登录用户下次拉取权限后生效。

## 6.6 权限管理

**FR-PERM-001 权限点列表**

- 按模块分组展示权限点；
- 每个权限点包含编码、名称、类型、所属菜单、状态；
- 支持搜索和筛选。

**FR-PERM-002 权限点维护**

- 支持新增、编辑、启用、停用；
- 权限编码唯一，格式建议为 `模块:动作`，例如 `user:create`；
- 已绑定角色的权限停用后，对应接口立即拒绝访问。

**FR-PERM-003 权限点类型**

- `menu`：菜单可见性；
- `action`：按钮、导出、删除等页面操作；
- `api`：后端接口权限；
- `data`：数据范围权限，首期保留枚举，实际数据范围后置。

## 6.7 业务数据管理

**FR-DATA-001 导入批次列表**

- 查看商号、单号、柜号、导入时间、状态、成功/警告/失败数量；
- 支持搜索、状态筛选、日期筛选；
- 可查看导入问题明细。

**FR-DATA-002 源文件管理**

- 查看原始文件名称、内容哈希、关联批次、上传时间；
- 支持下载和查看文件状态；
- 不提供直接覆盖业务键的快捷操作，覆盖仍走现有导入流程。

**FR-DATA-003 数据问题查看**

- 查看 `data_issue` 明细，包括行号、字段、等级、严重程度和原始值；
- 支持导出问题明细。

**FR-DATA-004 AI 分析缓存**

- 查看 AI 缓存记录、模型、生成时间和缓存键；
- 支持手动刷新指定缓存或清空过期缓存；
- 刷新和清空操作需记录审计日志。

## 6.8 审计日志

**FR-LOG-001 登录日志**

- 记录用户名、登录结果、IP、User-Agent、时间；
- 支持按用户名、结果和时间筛选；
- 对连续失败登录可展示，不自动封禁。

**FR-LOG-002 操作日志**

- 记录操作者、模块、动作、目标对象、结果、IP、时间和变更摘要；
- 支持按模块、操作者和时间筛选；
- 支持导出 CSV；
- 操作日志只读，管理员不能通过界面修改或删除。

## 6.9 系统配置

**FR-CONF-001 基础配置**

- 公开注册开关；
- 会话默认有效期、记住登录有效期；
- 密码最小长度等安全策略；
- AI 分析功能开关和默认模型配置，密钥不回显。

## 7. 权限与菜单映射

### 7.1 果农端菜单与权限点

| 页面 | 路由 | 建议权限点 |
| --- | --- | --- |
| 卖得怎么样 | `/overview` | `biz:overview:view` |
| 每一单 | `/settlements` | `biz:settlements:view` |
| 数据导入 | `/imports` | `biz:imports:view`、`biz:imports:create` |
| 结算单详情 | `/settlement-detail` | `biz:settlement-detail:view` |
| 结算单对比 | `/settlement-comparison` | `biz:settlement-comparison:view` |
| 品牌对比 | `/series-comparison` | `biz:series-comparison:view` |

### 7.2 管理端菜单与权限点

| 页面 | 路由 | 建议权限点 |
| --- | --- | --- |
| 管理端工作台 | `/admin/dashboard` | `admin:dashboard:view` |
| 用户管理 | `/admin/users` | `admin:user:view/create/update/delete/reset-password/disable` |
| 角色管理 | `/admin/roles` | `admin:role:view/create/update/delete/grant` |
| 菜单管理 | `/admin/menus` | `admin:menu:view/create/update/delete/sort` |
| 权限管理 | `/admin/permissions` | `admin:permission:view/create/update/delete` |
| 业务数据管理 | `/admin/data/*` | `admin:data:view/export/refresh-cache` |
| 审计日志 | `/admin/logs` | `admin:log:view/export` |
| 系统配置 | `/admin/settings` | `admin:config:view/update` |

### 7.3 权限命名约定

- 资源统一使用小写短横线；
- 动作统一为 `view`、`create`、`update`、`delete`、`export`、`grant`、`disable`、`reset-password`；
- 菜单级权限与页面级权限可复用，按钮级权限按页面再细分。

## 8. 安全要求

- 密码继续使用 Argon2 哈希，不落明文；
- 登录和权限判断全部在后端完成；
- 管理端接口默认拒绝未认证请求；
- 关键变更必须做二次确认；
- 登录日志、操作日志不可通过界面删除；
- 所有审计日志包含操作者、时间和结果；
- 防止越权：用户 A 不能查询或修改不属于其权限范围的资源；
- 防暴力破解：首期可记录失败登录，P1 增加失败锁定或验证码；
- 前后端接口返回中不得包含密码哈希、AI 密钥等敏感信息。

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可用性 | 管理端不阻塞果农端；管理端维护时果农端仍可正常访问 |
| 兼容性 | 支持主流现代浏览器，移动端至少保证可读和基本操作 |
| 可维护性 | 延续 Vue 3 + TypeScript + FastAPI + SQLAlchemy 技术栈 |
| 可扩展性 | 角色、菜单、权限可配置；新增页面不要求大量前端硬编码 |
| 性能 | 常规列表查询响应时间目标 ≤ 1s；菜单/权限加载目标 ≤ 300ms |
| 审计 | 关键操作日志保留至少 180 天，归档策略可后续定义 |
| 部署 | 无需容器化；沿用 Nginx + FastAPI + MySQL 的现有部署方式 |

## 10. 验收标准

### 10.1 用户与角色

- 管理员能创建、编辑、禁用、重置密码和删除用户；
- 用户列表能按角色、状态和关键词筛选；
- 禁用用户后，其旧会话不能继续访问受保护接口；
- 角色能绑定多个用户，用户能拥有多个角色。

### 10.2 菜单与权限

- 能新增目录、菜单和按钮；
- 能按角色勾选菜单和操作权限；
- 权限保存后，用户看到的菜单和可用按钮符合授权结果；
- 直接调用未授权 API 返回 `403`，不能靠前端绕过。

### 10.3 审计

- 用户、角色、菜单、权限的变更均可查到操作记录；
- 登录成功和失败均有日志；
- 审计日志只能查看和导出，不能修改或删除。

### 10.4 回归

- 现有果农端登录、注册、导入、分析和导出功能不受影响；
- 现有后端测试和前端测试全部通过；
- 数据库迁移脚本可重复执行且不破坏现有数据。

5. 操作日志需要保留多久，是否需要自动归档？
6. 连续登录失败是否需要锁定或验证码？
7. 管理端是否需要导出用户、角色、菜单和审计日志？
8. 现有 `fruits_ana` 后端是否允许在本次管理端建设中直接修改和新增迁移？

## 12. 推荐下一步
